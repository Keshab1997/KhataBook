# cloud-sync-google — Worker C

**Repository:** `Keshab1997/KhataBook` — attach this repo in Arena Agent Mode.
**Goal:** Build offline-first cloud sync for khatas and transactions with the Google sign-in UI (spec B5): a sync engine and scheduler that push pending local rows and pull remote changes through an injectable `CloudBackend`, the local-ledger support they need, and the Sign-in screen and Profile account card — all covered by tests. The Captain writes the Supabase adapter, app start-up and deep-link config after landing.
**Acceptance:**

1. **Backend contract.** `lib/features/sync/cloud_backend.dart` defines an abstract `CloudBackend`: the current user (id and email) and a stream of user changes; `signInWithGoogle()` (returns the user, or null when cancelled) and `signOut()`; `upsertKhatas` and `upsertTransactions`, which return the rows as the server stored them; and `fetchChanges(since)`, which returns khata and transaction rows whose `serverUpdatedAt` is after `since`, plus the new cursor. Row classes mirror the remote tables below (money as `int` paise, times as UTC `DateTime`). No Supabase import anywhere in this task.
2. **Remote schema (already live; the Captain owns it).** `khatas(user_id, id, name, opening_balance_paise, currency, sort_order, created_at, updated_at, deleted_at, server_updated_at)` and `transactions(user_id, id, khata_id, type, amount_paise, category_id, description, occurred_at, note_session_id, created_at, updated_at, deleted_at, server_updated_at)`, primary key `(user_id, id)`, RLS limited to the user's own rows, no deletes (tombstones only). The server keeps the row with the newer `updated_at` (on a tie a tombstone stays) and sets `server_updated_at` on every accepted write. A khata archive is `deleted_at` on `khatas`; unarchive clears it.
3. **Local ledger.** `LocalLedger` already sets `sync_state = 'pending'` and bumps `updated_at` on writes; keep that true for every write path. Add what the engine needs: read pending khatas and transactions; mark them synced only if `updated_at` is unchanged since they were read; apply remote rows (insert unknown ids, newer `updated_at` wins, a tie keeps a tombstone, never hard-delete, never overwrite a newer pending local row, applied rows become `synced`); a pending count; and storage for the cursor, last synced time, last error and the account id this device last synced with. Keep every existing public API and behaviour, and migrate any schema change through `onUpgrade`.
4. **Engine.** `SyncEngine.syncNow()` pushes khatas before transactions in batches, applies any returned row that differs from what was sent (the server kept a newer one), then pulls from the cursor with a 60-second overlap (applying is idempotent) and saves the new cursor and last synced time. Signed out or offline it is a no-op with a clear status, never an exception to the UI. A failure leaves local data untouched, records the error and retries with capped exponential backoff through a Timer-based `SyncScheduler` whose `kick()` is debounced for use after local writes (no new dependencies). If a different account signs in than the one this device last synced with, nothing is pushed until the user confirms.
5. **Status.** A `SyncStatus` stream: signed out · idle (last synced time, pending count) · syncing · error (reason, pending count).
6. **Sign-in screen (S11).** Explains that cloud backup is optional and that local data stays on the phone. A `Continue with Google` button calls `signInWithGoogle()`; the screen shows progress, cancel and errors, in English and Bengali through a `language` parameter (local en/bn pairs; don't edit `app_strings.dart`).
7. **Account card (S5 states).** A self-contained widget the Captain will place on Profile: local-only (hint "Sign in to enable cloud backup" and a Sign in button), signed in (email, `Last synced …`, `N pending`, `Back up now`, and `Log out` in `AppColors.expenseRed` behind a confirm), syncing (progress text only, never a blocking dialog), and error (reason and Retry). Backing up while offline shows a clear message and does nothing. Log out never deletes local data. Colours come only from `AppColors`.
8. **Tests.** `test/sync_test.dart` covers push → synced, idempotent re-push, a concurrent local edit staying pending, pull applying newer rows and ignoring older ones, tombstone and unarchive cases, server-kept-newer rows, failure → backoff with local data intact, the account-switch guard and the pending count, using an in-memory `LocalLedger` and `test/support/fake_cloud_backend.dart`. `test/account_card_test.dart` covers the four states, the log-out confirm and Bengali labels. `test/local_ledger_test.dart` stays green. This sandbox cannot run Flutter, so read every change for compile errors, keep `python3 tool/preflight.py` clean and match the existing `dart format` style; the Captain runs format, `flutter analyze --fatal-infos` and the full suite in review.
