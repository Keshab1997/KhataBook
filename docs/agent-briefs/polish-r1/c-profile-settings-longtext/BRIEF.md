# c-profile-settings-longtext — Worker C

**Repository:** `Keshab1997/KhataBook`
**Goal:** Profile and Settings are the two screens that visibly break, and the cause is the same: rows whose leading tile and right-hand chevron are laid out in a fixed-width `Row`, so at large text the label wraps to one or two words per line and the row grows taller than the screen. Restructure those shared row primitives, then finish the reference parity of the Profile screen (`docs/design/ui-preview.png`, screen 5: avatar, name, email, then My Wallet Summary / Backup to Supabase / App Settings / About App / Logout rows) so both screens are honest at 200% text on a 320 dp screen.
**Acceptance:**

1. **Long-text-safe rows.** Every settings/profile row must let its title and subtitle take the full remaining width, wrap onto multiple lines with a sensible `maxLines`/ellipsis strategy only when the content is genuinely secondary, keep the leading tile aligned to the first line (not vertically centred in a tall row), and keep the trailing chevron on the first line. At 320x568 with `textScaler` 2.0 both screens scroll with **zero** overflow and `tester.takeException()` is null — a test asserts it.
2. **Shared row primitive, one definition.** The row used by Profile and Settings is defined once in the allowed files and reused by both; no duplicated copy-paste layout. If the primitive lives in a file outside `allowed`, keep the copy inside the permitted file and say so in the report instead of touching the other file.
3. **Profile parity + honesty.** The header shows avatar, display name and account line (or the signed-out equivalent) with the existing artwork; the action list is ordered `My Wallet Summary`, `Backup / cloud`, `App Settings`, `About App`, `Logout`, each row keeping its existing key, route and enabled/disabled state. Things that do not exist yet keep their honest `Not available yet` chips — no fake functionality, no new route.
4. **Settings grouping + affordance.** `Preferences` and `Storage` groups read as panels with a clear heading, each row's current value is legible as a chip/badge without pushing the title onto one word per line, and the read-only banner stays. Bengali and English strings both come from the existing l10n layer — no hard-coded literals, no key renames.
5. **Screenshot-state contract.** `tool/screenshots/shot_registry.dart` (read-only, do not edit) expects `profile_small_large_text` and `settings_small_large_text`; your tests must cover the equivalent conditions (320 dp wide, textScaler 2.0, both languages) so those shots stay truthful.
6. **Tests.** Update `test/profile_settings_test.dart` and `test/settings_navigation_test.dart` (and `test/settings_language_test.dart` only if a string genuinely changes) with the long-text cases, the row-order contract and the no-overflow assertion. Every existing assertion in those files must keep passing.
