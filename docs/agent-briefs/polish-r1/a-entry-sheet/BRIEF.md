# a-entry-sheet — Worker A

**Repository:** `Keshab1997/KhataBook`
**Goal:** Make the Add Entry flow match the design reference in `docs/design/ui-preview.png` (screen 2, *Add Expense*) and the app's card/conversation grammar: a category **grid** (not a scrolling row), a real **After saving: preview**, an amount field that starts empty instead of showing a dead `₹0.00`, and a compact **bottom action sheet** instead of a full-screen route on short screens. Same treatment for the transaction editor, because it is the same form.
**Acceptance:**

1. **Category grid.** `category_picker.dart` renders every category in a wrapping grid — 4 columns at 390 dp, 5 fit on one row at 360 dp wide with 200% text still legible — each cell keeps its existing key, artwork/icon, label and selected state, shows the whole set (including the `More` affordance if present) without a horizontal scrollbar, and remains fully keyboard/semantics reachable. No category is hidden behind an overflow the user cannot discover.
2. **Amount starts empty.** On both screens the amount field begins with an empty text and a `₹` hint/placeholder (never the string `0.00`), keeps `TextInputType.numberWithOptions(decimal: true)`, rejects a leading-zero mess, and the Save button stays disabled until a positive amount is typed.
3. **"After saving:" preview is real.** Replace the current empty `After saving: —` line with a live one-line preview built from the chosen type + amount + khata's current remaining balance, e.g. `Expense ₹500 → remaining ₹5,920`. It updates on type/amount change, formats with the existing `core/format/money.dart` helpers (integer paise, en_IN grouping), and degrades to the current dash when no amount is entered. Balance comes from the screen's existing ledger state only — no new query, no arithmetic in the widget beyond adding the delta.
4. **Compact bottom sheet on short screens.** When the viewport is at or under the existing compact breakpoint (see how `add_entry_compact` is produced in `tool/screenshots/shot_registry.dart`), the form fits **without** the last section being clipped: the `Save Entry` action stays reachable and the sheet scrolls internally. Nothing overflows at 320x568 @200% text; a test asserts `tester.takeException()` is null there.
5. **Design parity on the header/first viewport.** Amount, Type toggle, Date, Category and Description are all visible in the first viewport at 390x844 **and** at 360x780, with the reference's spacing rhythm (label → field → next label). Use `AppColors`/`Theme.of(context)` only; no literal `Color(0x...)`.
6. **Tests.** Update `test/add_entry_screen_test.dart` and `test/transaction_editor_test.dart` so they cover the new grid layout, the empty amount, the live preview arithmetic, and the compact layout no-overflow assertion. Existing behaviour tests (validation, save payload, type switching, date picker) must keep passing — fix a test only where the new visual contract genuinely changed it, and say in your report which ones you changed and why.
